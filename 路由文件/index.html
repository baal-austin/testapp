应用入口模块 (main.py)

1. 模块概述

本模块是 FastAPI 应用的入口文件，负责：

  • 创建 FastAPI 应用实例

  • 配置应用生命周期（启动时创建数据库表，关闭时清理资源）

  • 注册所有路由模块

  • 提供根路径健康检查接口

通过 uvicorn 启动服务器，支持开发模式热重载。

2. 文件结构

text

main.py
├── 导入依赖
├── lifespan 函数（应用生命周期管理）
├── app 实例（FastAPI 应用）
├── 路由注册（包含所有业务模块的 router）
├── 根路径接口 read_root
└── 启动入口（if __name__ == "__main__"）

5. 函数说明

生命周期管理函数

函数名：lifespan

​参数​：

  • ​app: FastAPI – FastAPI 应用实例

​返回值​：AsyncContextManager[None] – 异步上下文管理器

​功能​：定义应用的生命周期行为。

  • ​启动阶段​：打印“启动应用...”，调用 create_db_tables() 初始化数据库表。

  • ​运行阶段​：yield 挂起，应用正常运行。

  • ​关闭阶段​：finally 块中打印“关闭应用，清理资源...”，可扩展关闭数据库连接池、缓存清理等操作。

​示例​：由 FastAPI 自动调用，无需手动调用。

根路径接口

端点：GET /

​函数名​：read_root ​参数​：无

​返回值​：Dict – {"message": "欢迎使用单词管理系统API"}

​功能​：根路径 GET 处理器，返回欢迎消息，可用于健康检查或 API 入口提示。

6. 数据流与核心逻辑

  1. ​启动阶段​：

    • 运行 uvicorn.run("main:app", ...) 启动服务器

    • FastAPI 调用 lifespan 上下文管理器

    • 执行 create_db_tables() 创建数据库表（若不存在）

    • 打印“启动应用...”

  2. ​运行阶段​：

    • 所有路由通过 app.include_router(...) 注册，客户端请求时根据路径分发至对应路由处理器

  3. ​关闭阶段​：

    • 应用接收到关闭信号（如 Ctrl+C）

    • 执行 lifespan 的 finally 块，打印“关闭应用，清理资源...”

认证路由模块 (auth.py)

1. 模块概述

本模块负责处理用户认证相关的所有 API 端点，包括：

  • 验证码发送（邮箱/手机）

  • 用户注册（支持邮箱、手机、微信、QQ）

  • 用户登录（支持邮箱、手机、微信、QQ）

  • 第三方账号绑定（微信、QQ）

  • 令牌验证与密码重置

所有接口均位于 /auth 路径前缀下，使用统一的响应格式与错误处理。

5. 函数说明

辅助函数

函数名：send_verification_message

​参数​：

  • ​identifier: str – 接收验证码的标识（邮箱地址或手机号）

  • ​code: str – 6位数字验证码

  • ​purpose: str – 验证码用途（如 "register"、"reset_password"）

​返回值​：无

​功能​：异步发送验证码消息。根据标识符是否包含 @ 判断为邮箱或手机：

  • 邮箱：调用 email_service.send_verification_email() 发送邮件

  • 手机：模拟短信发送（仅记录日志，需替换为真实短信服务）

​异常​：捕获异常并记录日志，不向上抛出。

路由端点

端点：POST /auth/send-verification-code

​函数名​：send_verification_code

​参数​：

  • ​request: SendCodeRequest – 包含 identifier（邮箱/手机号）和 purpose（用途）的请求体

  • ​background_tasks: BackgroundTasks – FastAPI 后台任务管理器

​返回值​：Dict – {"message": "验证码已发送"}

​功能​：

  1. 验证邮箱或手机号格式

  2. 生成6位随机验证码（通过 generate_verification_code()）

  3. 将验证码存储到数据库/缓存（store_verification_code()）

  4. 将发送任务加入后台队列，避免阻塞响应

  5. 返回成功消息

端点：POST /auth/register

​函数名​：register

​参数​：

  • ​register_request: RegisterRequest – 注册请求体，包含 login_type、identifier、password、display_name、verification_code 等字段

  • ​db: Session – 数据库会话（依赖注入）

​返回值​：Token 结构，包含 access_token、token_type、user_id、username、has_password、auth_provider

​功能​： 根据登录类型执行不同注册逻辑：

  • ​邮箱/手机​：验证验证码，检查标识符是否已存在，创建普通用户（需密码）

  • ​微信​：通过 WechatAuthService 用授权码换取 access_token 和 openid，再获取用户信息（unionid 等），创建微信用户

  • ​QQ​：通过 QQAuthService 用授权码换取 openid，创建 QQ 用户

  • 其他类型：返回 400 错误

注册成功后生成访问令牌并返回。

端点：POST /auth/login

​函数名​：login

​参数​：

  • ​login_request: LoginRequest – 登录请求体，包含 login_type、identifier、password（邮箱/手机）、auth_code（微信/QQ）

  • ​db: Session – 数据库会话

​返回值​：Token 结构（同注册）

​功能​： 根据登录类型执行不同认证逻辑：

  • ​邮箱/手机​：调用 authenticate_email_user / authenticate_phone_user 验证密码

  • ​微信​：用授权码获取用户信息，通过 authenticate_wechat_user 查询用户

  • ​QQ​：用授权码获取 openid，通过 authenticate_qq_user 查询用户

成功后更新最后登录时间，生成访问令牌并返回。

端点：POST /auth/bind-third-party

​函数名​：bind_third_party

​参数​：

  • ​bind_request: BindThirdPartyRequest – 包含 provider（"wechat"/"qq"）和 auth_code（授权码）

  • ​db: Session – 数据库会话

  • ​current_user: User – 当前登录用户（通过 JWT 认证依赖注入）

​返回值​：Dict – {"message": "绑定成功"}

​功能​：

  1. 根据 provider 调用对应第三方服务获取用户唯一标识（微信 unionid，QQ openid）

  2. 检查该标识是否已被其他用户绑定

  3. 若未被占用，调用 bind_third_party_to_user 将标识绑定到当前用户

  4. 返回成功消息

端点：POST /auth/verify-token

​函数名​：verify_access_token

​参数​：

  • ​token: str – JWT 访问令牌（在请求体中）

​返回值​：Dict – {"valid": bool, "username": str, "user_id": int}

​功能​： 调用 verify_token 解码并验证令牌的有效性（签名、过期时间等）。若有效，返回令牌中的用户信息；若无效，返回 401 错误。

端点：POST /auth/reset-password

​函数名​：reset_password

​参数​：

  • ​reset_request: ResetPasswordRequest – 包含 identifier、code（验证码）、new_password

  • ​db: Session – 数据库会话

​返回值​：Dict – {"message": "密码重置成功"}

​功能​：

  1. 验证验证码（通过 verify_code）

  2. 根据标识符查找用户

  3. 验证新密码强度（validate_password_strength）

  4. 哈希新密码并更新数据库

  5. 返回成功消息

6. 数据流与核心逻辑

  1. ​发送验证码​：前端提供邮箱/手机 → 后端校验格式 → 生成验证码 → 存储 → 后台发送 → 返回成功

  2. ​注册​：

    • 邮箱/手机：验证码校验 → 检查标识符是否已存在 → 创建用户（哈希密码） → 生成令牌

    • 微信/QQ：OAuth2.0 流程（用授权码换取用户信息） → 创建或绑定用户 → 生成令牌

  3. ​登录​：根据类型验证凭证（密码或第三方标识） → 更新登录时间 → 生成令牌

  4. ​绑定第三方​：获取第三方标识 → 检查冲突 → 绑定到当前用户

  5. ​令牌验证​：解码 JWT 并返回有效信息

  6. ​重置密码​：验证码校验 → 更新密码

7. 运行说明

本模块是 FastAPI 应用的一部分，通过 main.py 中的 app.include_router(auths_router) 注册。启动应用后，所有认证接口即可通过 /auth 前缀访问。

8. 附录

  • 依赖的服务类（WechatAuthService、QQAuthService）需在 app/services/third_party_auth.py 中实现具体 OAuth 逻辑。

  • 验证码存储函数（store_verification_code、verify_code）通常使用 Redis 或数据库临时表，需确保其实现正确。

  • 密码强度验证函数 validate_password_strength 应包含最小长度、字符组合等规则。

笔记路由模块 (note.py)

1. 模块概述

本模块负责处理笔记相关的所有 API 端点，包括：

  • 笔记的创建、读取、更新、删除

  • 笔记列表获取（支持分页、关键词搜索、可见性过滤）

  1. ​关系管理​：管理员通过 CRUD 接口维护单词之间的关系，关系可携带强度（0-1）和描述，并可关联多个关系类型。

6. 数据流与核心逻辑

  1. ​获取当前用户​：通过 get_current_user 依赖注入，该依赖会解析 JWT 并查询数据库返回用户对象，直接返回即可。

  2. ​获取其他用户​：通过用户 ID 查询数据库，返回时使用 UserPublicResponse 模型自动过滤敏感字段。

  3. ​更新用户信息​：仅允许更新模型 UserUpdate 中定义的字段，避免非法修改。更新前确保用户存在，然后逐一设置字段并保存。

  4. ​单设备登出​：将当前令牌添加到 Redis 或数据库黑名单中，后续验证时会检查该令牌是否在黑名单内。

  5. ​全局登出​：更新用户表中的 last_logout_at 字段。验证令牌时，如果令牌的签发时间（iat）早于该字段，则视为无效，从而实现一次操作使所有令牌失效。

8. 附录

  • 令牌黑名单机制：add_to_blacklist 通常将令牌存储到 Redis 或数据库缓存中，设置过期时间（与令牌有效期相同）。

  • 全局登出依赖 last_logout_at 字段，需要在 JWT 生成时包含 iat 声明，并在令牌验证时检查 iat 是否大于用户的 last_logout_at。该逻辑已在 get_current_user 依赖中实现。

  • 用户更新接口允许的字段在 UserUpdate 模型中定义，可根据需要扩展。

  • ​db: Session – 数据库会话

​功能​：通过标签名称获取关联的所有单词。若标签不存在返回 404。

6. 数据流与核心逻辑

  1. ​单词标签管理​：管理员可为单词添加或移除标签，用户可查看单词的标签列表。

  2. ​全局标签管理​：管理员维护标签库（创建、更新、删除），普通用户可查询标签列表。

  3. ​标签与单词关联​：通过中间表（word_tag）维护多对多关系。删除标签时会自动清理关联记录。

  4. ​权限控制​：所有修改操作（添加、移除、创建、更新、删除）均需管理员权限。

8. 附录

  • 标签包含 name（唯一）和 type（如“难度”、“考试”、“词性”等）字段，可根据需要扩展。

词库路由模块 (wordbook.py)

1. 模块概述

本模块负责处理词库（单词集合）相关的 API 端点，包括：

  • 词库的创建、读取、更新、删除

  3. ​词库详情​：用户查看词库时，系统检查可见性并返回详情，包含关联单词列表、创建者信息、当前用户是否收藏。

  4. ​词库管理​：创建者可修改词库属性、添加/移除单词、删除词库。

  5. ​收藏功能​：用户可收藏公开词库，收藏后可在“我的收藏”列表中查看。

8. 附录

  • 词库的可见性（is_public）决定哪些用户可查看和收藏。公开词库所有人可见，私密词库仅创建者可见。

  • 词库与单词通过中间表（wordbook_word）建立多对多关系，可存储自定义顺序和备注。

  • 收藏功能使用独立收藏表（user_wordbook_collect）记录，不影响词库本身的可见性。

  • 删除词库时，仅删除关联关系，单词本身不受影响。
